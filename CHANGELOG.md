# Changelog

## [Unreleased]

## [2.0.0]

This is the first published version since 1.0.12. Versions 1.1 and 1.2 were
never published, so this section lists every change since 1.0.12. If you
regenerate code from 1.0.12 with this version, read "Breaking changes since
1.0.12" first: the generated code of every backend changed, and most
backends no longer exchange the same bytes with code generated by 1.0.12
(DDS-XTypes 1.3 7.4 is the reference for the wire changes below).

### Breaking changes since 1.0.12

#### API

Generator, library and command line (details under "Breaking changes"):

- A leading underscore escapes an identifier (IDL 4.2 7.2.3.2): generated
  names, TypeObject member names and `@autoid(HASH)` ids of such names change.
- Two enumerators of one enum with the same value, and an enumerator outside
  the integer width its `@bit_bound` selects, are now refused at load. Such an
  IDL generated silently before (DDS-XTypes 1.3 Table 4 and Table 32).
- `Annotation::Custom`, `Annotation::Topic`, and `Annotation::Value` / `Min` /
  `Max` / `Range` have new field types.
- `IdlType::Named` and union case labels keep the leading `::` of an absolute
  name.
- `string<N>` and `wstring<N>` are parsed as `IdlType::BoundedString { wide,
  bound }`, no longer as a bounded `sequence<char, N>` / `sequence<wchar, N>`;
  a real `sequence<char>` is a sequence of char in every backend.
- The preprocessor moved from the binary into the library
  (`hddsgen::preprocessor`).
- Names resolve by the IDL 4.2 scoping rules (7.5), constants are scoped, and a
  reopened module is no longer merged into its first opening: IDL that was
  accepted before can be refused, and the generated declaration order changes.
- `hddsgen gen` generates nothing when the validator reports an error; a
  missing `#include`, the collisions Cyclone DDS refuses and duplicate member
  names are errors.
- The C and Rust backends emit IDL constants.
- An un-annotated struct, union, enum or bitmask is APPENDABLE (see "Wire
  format"); it changes the TypeObject of every backend that emits one.

Rust:

- The generated code must be built against an `hdds` whose derive and TypeObject
  model match (HDDS 1.5.0); against an older `hdds` it does not compile. A guard
  at the top of every generated file says so.
- The `DDS` trait implementation provides `encode(buf, CdrVersion)` and
  `decode(buf, CdrVersion)` instead of `encode_cdr2` / `decode_cdr2`, and
  declares `encodes_xcdr1_natively()` and `nested_type_objects()`.
  `Cdr2Encode` / `Cdr2Decode` implementations provide `encode_cdr2_le_at` /
  `decode_cdr2_le_at`.
- The inherent `encode_cdr2_le` / `decode_cdr2_le` of a generated type are
  replaced by one pair per version, `encode_xcdr1_le` / `encode_xcdr2_le` and
  `decode_xcdr1_le` / `decode_xcdr2_le`, with `_at` variants; the
  `Cdr2Encode` / `Cdr2Decode` implementations delegate to them.
- `compute_key` (an FNV-1a digest) is gone from the `DDS` implementation;
  keyed types provide `write_key_holder`, `encode_key`,
  `key_hash_of_key_payload` and `keys_round_trip`. A key of a map, `fixed`,
  `long double`, `@optional` or a collection of non-primitives gets no hook.
- `max_cdr2_size` is the exact size of the value, computed by a measuring
  encode, instead of a constant bound (`max_xcdr1_size` and `max_xcdr2_size`
  likewise).
- A `sequence<char>` / `sequence<wchar>` member is a `Vec` of its element, a
  sequence on the wire (see "Wire format"); a `string<N>` member is a `String`.

Rust micro (`micro`):

- An `@optional` member is an `Option<T>`.
- A derived structure holds a `base` member and serializes it first.
- An enumeration gains `from_i32`, and an unknown enumerator is reported as
  `DecodingError` instead of `InvalidEncoding`; a union without a default
  branch reports `DecodingError` for a discriminator no case selects.
- `ENCODED_SIZE_MAX` is recomputed so that it bounds the largest encoding of
  the type; it grows for some types and shrinks for others (a buffer sized from
  a 1.0.12 constant may be wrong).
- `compute_key` returns the RTPS KeyHash (see "Wire format"); a key inherited
  from a base structure is refused.
- A struct member of a map, bitmask, bitset or `fixed` type, and any struct
  holding one, is refused at generation. The 1.0.12 output for these did not
  compile.

C:

- Every type declared in a module is named with its full module path:
  `Comp::Msg` is `Comp_Msg` (was `Msg`), its enumerators `COMP_COLOR_RED`, and
  the descriptor and codec function prefixes are the snake-case scope segments
  (`comp_msg_type_descriptor`), and a function name gains the module path too
  (`P::LongKey` becomes `P_LongKey` and `longkey_encode_cdr2_le` becomes
  `p_longkey_encode_cdr2_le`; the enumerator `COLOR_BLUE` of `X::Color` becomes
  `X_COLOR_BLUE`). The type descriptor reports the IDL qualified name
  (`Comp::Msg`, was `Msg`) and its hash changes with it. A type outside any
  module keeps its name. Two names that give the same C name
  (`a::b_T`, `a_b::T`) are refused.
- `cdr_align`, `cdr_add`, `cdr_pad`, `cdr_need_write`, `cdr_need_read` and
  `cdr_skip` are no longer defined by the header; the codec uses the
  `hdds_x2c_*` runtime emitted in each header. `CDR_SIZE_WCHAR` is 2 (was 4).
- `T_decode_cdr2_le` and `T_decode_cdr2_le_at` obtain no storage: for a type
  holding an unbounded string, a sequence or a map they return
  `-CDR_OUT_OF_MEMORY` (new code, 4) whatever the data. Use
  `T_decode_cdr2_le_alloc` / `T_decode_cdr2_le_at_alloc` with an
  `hdds_x2c_alloc_fn` (the header provides `hdds_x2c_arena_init` and
  `hdds_x2c_arena_alloc`). The decoder never writes through a pointer the
  caller set. There is no compile error: existing callers fail at run time.
- A `string<N>` member is `char[N+1]` and a `wstring<N>` member `wchar_t[N+1]`;
  a `sequence<char>` / `sequence<wchar>` member is a sequence holder
  (`{ T* data; uint32_t len; }`) instead of `char*` / `char[N+1]`.
- A bitmask typedef is as wide as its `@bit_bound` (`uint32_t` by default, was
  `uint64_t`).
- `T_max_cdr2_size` is the exact size of the value, including DHEADERs, instead
  of a hand-computed bound.
- A member is declared through a C declarator, so multi-dimensional arrays
  compile (`octet m[2][3]`).
- `T_compute_key` returns the RTPS KeyHash (see "Wire format").

C-micro (`c-micro`):

- Types declared in nested modules gain the outer path (`b_T` becomes `a_b_T`).
- An `@optional` member has a `has_<member>` flag; a derived structure holds its
  `base`.
- A `string<N>` holder is `char[N+1]` (was `char[N]`); a `wchar` is a
  `uint16_t` and a `wstring` an array of `uint16_t` UTF-16 units.
- Typedefs and bitmasks are declared (they were silently dropped).
- `<TYPE>_ENCODED_SIZE_MAX` is an upper bound computed from the holders; it
  grows for some types and shrinks for others.
- A map, a bitset or `fixed` is refused at generation, with an error naming
  the type and the reason (the 1.0.12 output for these did not compile).
- A sequence count above the holder's capacity is refused on both sides.
- `T_compute_key` returns the RTPS KeyHash (see "Wire format").

C++:

- C++17 is required by every generated header (`std::optional`, `if constexpr`,
  non-const `std::wstring::data()`); a header compiled with `-std=c++14` can
  fail, including types without optional members.
- A bounded `sequence<T, N>` is `std::vector<T>` (was `std::array<T, N>`, always
  N elements on the wire); the bound is enforced on encode and decode.
  `string<N>` and `wstring<N>` stay `std::array<C, N>`.
- In the FastDDS-compatible flavour, members are `protected` (were `private`).
- `encode_cdr2_le` / `decode_cdr2_le` return -1 on any error (were the inner
  code). A decode that exceeds its storage budget returns -1 before reserving
  anything.
- `PubSubType::compute_key` returns the RTPS KeyHash (see "Wire format").
- A decoder refuses an enumeration value that names no literal and a presence
  flag other than 0 or 1.
- `long double` is written as the 8-byte double the data model sizes it as.

Python:

- A type declared in a module is the class `a_b_T` (`Comp::Msg` is `Comp_Msg`);
  each module is also a class (`Comp.Msg`) and the unqualified name stays bound
  when it is unique in the file. `type_name()` returns the scoped IDL name
  (`Comp::Msg`, was `Msg`), which is the DDS type name the type announces. A
  module constant is `Comp_MAGIC` (also `Comp.MAGIC`).
- Member defaults follow DDS-XTypes 1.3 Table 9: an enumeration defaults to its
  first literal (was 0), an array to its dimensions of defaults (was an empty
  list), a union to its discriminator's default.
- The `case` property of a union's `default` branch returns its value only when
  no other label matches (it returned it for every discriminator), and union
  labels are compared as integers.
- A decoded `char` is its unsigned code (was signed).
- `compute_key` takes `protected_key=False` and returns the RTPS KeyHash.
- Malformed input (a bound exceeded, an array of the wrong length) raises
  `ValueError`; a `fixed` member raises `NotImplementedError` at encode,
  decode and key encode (the member was silently skipped).

TypeScript:

- A type declared in a module is generated at the top level under its flat name
  (`a::b::T` is `a_b_T`, `encodea_b_T`, `decodea_b_T`, `computeKeya_b_T`); the
  module namespaces re-export the declarations under their own names, so
  `M.T` and `M.encodeT` keep working. Every module level is generated (nested
  modules were dropped); `encodeKey`, `hasKey`, `keySupported` and
  `extensibility` exist at the top level only.
- `Cdr2Buffer.align()` caps at 4 and measures from the origin of the buffer;
  the codec uses aligned `put*` / `get*` methods, and the fields of
  `Cdr2Buffer` are `protected`.
- Enumeration and bitmask `encode` / `decode` functions work at the `@bit_bound`
  width; a bitmask decodes to its own type; a 64-bit bitmask is a `bigint` and
  its flag values are positive hex literals.
- A decoder throws for an enumeration value that names no literal.
- A `fixed` member throws (it was written as a float64, which is not the IDL
  `fixed` representation).
- A derived interface extends its base, and `computeKey` of a type keyed in its
  base hashes the base key members (it returned 16 zero bytes).
- A union type admits `{ discriminator }` alone, the form of a discriminator no
  case selects.

Decoder bounds (new behaviour, see "Added"):

- Rust: a collection whose storage exceeds `MAX_ALLOC_RATIO` (64) times the
  bytes of the body is refused (`InvalidEncoding`); the elements that take no
  byte on the wire are bounded by `MAX_ZERO_WIRE_ELEMENTS` (1024) over the whole
  decode. A valid sample whose collections need more
  memory than that (for example a body of absent `@optional` members) is now
  refused.
- C, C++, Python and TypeScript apply the same two bounds
  (`CDR_MAX_ALLOC_RATIO`, default 64, and `CDR_MAX_ZERO_WIRE_ELEMENTS`, default
  1024) to the whole decode, however the collections nest; C refuses with
  `-CDR_OUT_OF_MEMORY` or `-CDR_INVALID_DATA`.

#### Wire format

All backends:

- **An enumerator with no explicit value is numbered as the previous value plus
  one.** The Rust, Rust micro, C-micro and TypeScript backends numbered it by
  its position, so code already generated from an IDL that mixes explicit and
  implicit enumerators changes value: `enum E { A, B = 10, C }` gave `C = 2`
  there and now gives 11, which is what the Python, C and C++ backends always
  produced. Regenerate every language from the same IDL together; a peer still
  running the old Rust or TypeScript output will disagree on the wire.
- A struct, union, enum or bitmask without an extensibility annotation is
  APPENDABLE (was FINAL): a DHEADER under XCDR2 and `IS_APPENDABLE` in the
  TypeObject. Use `--default-extensibility final` for the old layout. The
  micro backend is XCDR1 only, where an APPENDABLE structure has no DHEADER, so
  its bytes do not change for this.
- The KeyHash of a keyed instance is the RTPS 2.5 value (9.6.4.8: the key
  members serialized as PLAIN_CDR2, big endian, zero-padded to 16 bytes, MD5
  when the key can exceed 16 bytes) instead of an FNV-1a digest that no other
  implementation computes. Every backend changes: Rust, micro, C, C-micro, C++,
  Python and TypeScript. A peer generated by 1.0.12 computes another value for
  the same instance.

Rust:

- Member ids of a `@mutable` type without `@id` are the DDS-XTypes sequential
  ids (7.3.1.2.1.1; MD5 name hash under `@autoid(HASH)` and `@hashid`), base
  members first. 1.0.12 used an FNV-1a name hash on the wire, in the TypeObject
  and in the key-only payload.
- `@appendable` was encoded as FINAL and announced `IS_FINAL`: it now carries a
  DHEADER under XCDR2, the FINAL form under XCDR1, and `IS_APPENDABLE`.
- A `@mutable` structure has its DHEADER and aligned EMHEADER1 under XCDR2 and
  is a parameter list under XCDR1 (1.0.12 sent XCDR2 bytes under an XCDR1
  header).
- Enumerations are as wide as their `@bit_bound` (1, 2 or 4 bytes; was 4),
  bitmasks as wide as theirs (was 8), union discriminators as wide as their
  type, `wchar` is 2 bytes and `wstring` is UTF-16 counted in bytes without NUL
  (were 4 bytes and UTF-8).
- Sequences and arrays of non-primitive elements carry a DHEADER; nested values
  align against the origin of the stream (reset at each XCDR1 parameter), not
  their own first byte; the elements of a `sequence<8-byte>` align at 8 under
  XCDR1; XCDR2 aligns at most at 4.
- `@optional` members of FINAL and APPENDABLE structures are XCDR1 parameters;
  XCDR2 is a presence byte followed by the value.
- A union `case 1: case 2:` decodes discriminator 2 into that branch (it fell
  into the default branch).
- The TypeObject of a type changes (member flags `TRY_CONSTRUCT1`, `IS_KEY`,
  `IS_OPTIONAL`, `IS_MUST_UNDERSTAND`, `IS_EXTERNAL`, struct flags
  `IS_AUTOID_HASH` and `IS_NESTED`, `base_type`, the enum `bit_bound`, plain
  identifiers for strings, sequences, arrays and maps, objects for unions,
  bitmasks and aliases), so its hash differs from 1.0.12's.
- Bounds of strings and sequences are enforced on encode and decode.

Rust micro (`micro`, XCDR1):

- Enumerations are as wide as their `@bit_bound` (was 4 bytes), union
  discriminators as wide as their type, `wchar` is 2 bytes and `wstring` UTF-16
  (were 4 bytes and UTF-8).
- `@mutable` is a parameter list (it was encoded as FINAL), and an `@optional`
  member of a FINAL or APPENDABLE structure is a parameter (it was dropped).
- A derived structure serializes its base members (they were dropped).
- An un-annotated type keeps its bytes (APPENDABLE has no DHEADER in XCDR1),
  although the generator prints its APPENDABLE info line for it.

C:

- Types without an extensibility annotation get the DHEADER; `@appendable` and
  `@mutable` were encoded as FINAL and now carry their DHEADER and EMHEADER1.
- Enumerations are as wide as their `@bit_bound`, bitmasks as wide as theirs
  (was 8 bytes), union discriminators as wide as their type; `wchar` is 2 bytes
  and `wstring` is UTF-16 counted in bytes without NUL.
- 8-byte primitives align at 4 (they padded to 8), measured from the start of
  the buffer the entry point received, so a nested value aligns where it lands
  in the stream.
- Collections of non-primitive elements carry a DHEADER.
- `string<N>` is encoded as a string (it was a sequence of char without NUL);
  `sequence<char>` / `sequence<wchar>` are encoded as sequences, an element
  count followed by the elements (they were written as strings).
- Base structure members are serialized first (they were not).
- `@optional` members of FINAL and APPENDABLE structures carry a presence byte.
- Members are written byte by byte, little endian (the 1.0.12 `_le` functions
  copied the host representation).
- Padding is zero.

C-micro:

- Same wire changes as C: `@appendable` and `@mutable` framing, enumeration,
  bitmask, union discriminator, `wchar` and `wstring` widths, DHEADERs of
  collections, base members, `@optional` presence byte, `string<N>` and
  `sequence<char>`.
- 8-byte primitives align at 4 (they aligned at 8).
- Union discriminators take their type's width (every primitive discriminator
  was written as 4 bytes).

C++:

- Types without an extensibility annotation get the DHEADER; the DHEADER of a
  nested APPENDABLE structure is aligned and an APPENDABLE union has one (it had
  none).
- Member ids of a `@mutable` type without `@id` are the sequential ids
  (7.3.1.2.1.1; MD5 under `@autoid(HASH)` and `@hashid`), not an FNV-1a name
  hash; `@mutable` members use aligned EMHEADER1 with the length code the value
  needs (strings and collections use the value's own length word, with NEXTINT
  for length code 4 only).
- Enumerations, bitmasks, union discriminators, `wchar` and `wstring` as for C
  (`wchar` is one UTF-16 unit; `wstring` has no NUL; were `wchar_t` bytes with a
  NUL).
- 8-byte primitives and bitmasks align at 4 (they aligned at 8); nested values
  align against the stream, not their own sub-buffer; padding is zero.
- A bounded `sequence<T, N>` is a count followed by the elements it holds (it
  always wrote N elements); `string<N>` is a string (it was written as N chars
  with count N); `sequence<char>` is a sequence.
- Collections of non-primitive elements carry a DHEADER; base members are
  serialized; an `@optional` member is a presence byte followed by the value,
  and a flag other than 0 or 1 is refused.

Python:

- Types without an extensibility annotation get the DHEADER; the alignment of
  8-byte primitives is at most 4 and of nested values is from the origin of the
  stream.
- Member ids and framing of `@mutable` types as for C++ (sequential ids,
  aligned EMHEADER1, length codes).
- Enumeration, bitmask and union discriminator widths follow their type; a
  bitmask's standalone `encode_cdr2_le()` is its `@bit_bound` width (was 8
  bytes); `wchar` is one UTF-16 unit (was 4 bytes) and a `wstring` is
  serialized, a byte length followed by UTF-16 units without NUL (it was not
  serialized).
- A member whose type is a bitmask typedef is serialized (it was not).
- A union used as a member is serialized (it was absent) and a discriminator no
  case selects is serialized alone.
- Base members are serialized; collections of non-primitive elements, and maps,
  carry a DHEADER; `string<N>` is a string and `sequence<char>` a sequence.

TypeScript:

- Types without an extensibility annotation get the DHEADER; padding is
  written as zero bytes; the presence flag of an `@optional` member is not
  aligned; 8-byte primitives align at most at 4.
- Member ids and framing of `@mutable` types as for Python.
- Enumeration, bitmask and union discriminator widths follow their type (a
  bitmask was 8 bytes); `wchar` is one UTF-16 unit (was 4 bytes, typed as a
  string) and `wstring` is a byte length followed by UTF-16 units without NUL
  (was UTF-8 with a NUL).
- Union labels are all matched (only the first was), a union as a member is
  serialized, and a discriminator no case selects is serialized alone.
- Base members are serialized and a base key is hashed; collections of
  non-primitive elements carry a DHEADER; `string<N>` is a string and
  `sequence<char>` a sequence.

#### MSRV and toolchain

- hddsgen itself: `Cargo.toml` declares no `rust-version` in 1.0.12 or in
  2.0.0; the edition is 2021 in both. The minimum supported Rust version of
  the generator is unchanged.
- Generated Rust: the code must be built against `hdds` 1.5.0 (see "API"). It
  uses `std::sync::OnceLock` for the hash of a type's TypeObject identifier
  (stable since Rust 1.70).
- C++: C++17 is required for every generated header (see "API"). The headers
  were documented as C++17 compatible in 1.0.12, but those of types without
  optional members also compiled as C++14.
- C: the default output stays C99 (C11 and `--c-standard c89` are available);
  the `--c-standard c89` output now compiles with `gcc -std=c89
  -pedantic-errors` (no `//` comments, no trailing enum comma, no empty
  initializer, no `ull` literal; it still includes `<stdint.h>`).
- C-micro: the documented standard is C99 (was "C89/C99"); the SDK runtime
  header `hdds_micro_cdr.h` uses `inline`.
- Python: unchanged, 3.7+ with `@dataclass`.
- TypeScript: the generated files type-check under `tsc --strict`; no runtime
  or compiler version requirement is stated in the commits.

### Breaking changes

- **A leading underscore escapes an identifier** (IDL 4.2 7.2.3.2): `_map` is
  the identifier `map`, never a keyword, and the underscore is no longer part
  of the name. Every generated name, TypeObject member name and `@autoid(HASH)`
  member id of a type whose IDL spells a name with a leading underscore
  changes accordingly (`long _id;` is now the member `id`, as other IDL
  compilers read it). The pretty-printer escapes a name again when it is an
  IDL keyword (case-insensitively, as the collision rule 7.2.3.1 reads).
  What follows the underscore must begin with a letter: `_1x` and `__x` are
  refused.
- `Annotation::Custom` parameters are `Vec<AnnotationParam>` (name, value,
  `AnnotationParamKind`: identifier, string, number, boolean) instead of
  `Vec<(String, String)>`; a string value is stored unquoted and unescaped.
- `Annotation::Topic` is `Topic { name, platform }` (both `Option<String>`).
- `IdlType::Named` keeps the leading `::` of an absolute name (`::T`), and a
  union case label keeps it too (`::m::A`).
- The preprocessor moved from the binary into the library
  (`hddsgen::preprocessor`).
- `Annotation::Value`, `Min`, `Max` and `Range` hold an `AnnotationParam`
  (value and literal kind) instead of a `String`.
- **Names resolve by the IDL 4.2 scoping rules (7.5) everywhere**: an
  unqualified name no enclosing scope declares is an error even when a
  single module elsewhere declares it (it was accepted, and reported
  "ambiguous" when several did), and a qualified name `a::T` is looked up
  in the `a` its first segment finds from the innermost scope, nowhere
  else (`Inner::X` where the innermost `Inner` lacks `X` is refused, as
  Cyclone DDS refuses it).
- Constants are scoped: a constant name resolves like a type name, so a
  module declaring its own `MAX` no longer changes what `MAX` means at the
  root (it did: one global table, the last declaration won).
- A union case label naming a constant is stored as the constant's value.
- A reopened module is no longer merged into its first opening: the AST
  keeps each `module M { ... };` where it is written, so declarations keep
  their order (IDL that uses, in a reopened module, a type of a module
  declared after the first opening generated C, c-micro and C++ that did
  not compile, and `fmt` wrote IDL Cyclone DDS refuses).
  `scope::merge_reopened_modules` merges them (the Rust and micro
  backends do, Rust modules cannot be reopened).
- `hddsgen gen` runs the validator and generates nothing when it reports
  an error (warnings are printed and do not stop it).
- A missing `#include` is an error (it was skipped, dropping every
  declaration of the file).
- Collisions Cyclone DDS refuses are errors (IDL 4.2 7.2.3.1, 7.5.2): a
  member spelled like its struct or union, two names of one scope equal
  case-insensitively (types, constants, modules, and enumerators, which
  belong to the scope enclosing their enum), two bitfields of a bitset.
  A member differing from its struct or union only by case is a warning
  accepted for ROS 2 compatibility (`unique_identifier_msgs::msg::UUID`).
- The C backend emits constants (`#define m_MAX (8)`); the Rust backend
  too (`pub const MAX: i32 = 4;`).
- Duplicate member names in a struct or union (`long _a; long a;`,
  `long a, a;`, or names differing only in case) are a validation error.

- **A struct, union, enum or bitmask without an extensibility annotation is
  generated as APPENDABLE**, the default DDS-XTypes 1.3 specifies
  (7.3.1.2.1.8: such a type "shall be considered appendable"). hddsgen 1.0.12
  generated it as FINAL. In every backend but micro the sample of such a
  struct or union now carries a DHEADER under XCDR2, its TypeObject says
  `IS_APPENDABLE` (`enum_flags` / `bitmask_flags` too), and in the Rust
  backend its key-only payload follows. XCDR1 bytes of a struct or union do
  not change (an APPENDABLE type is PLAIN_CDR under XCDR1). A peer generated
  by hddsgen 1.0.12 from the same un-annotated IDL announces FINAL and does
  not match. `--default-extensibility final` gives the FINAL layout back;
  without the option `hddsgen gen` prints an info line naming the types
  concerned.
- Rust generated code must be built against an `hdds` whose derive and
  TypeObject model match (HDDS 1.5.0).

### Added

- Multiple declarators (IDL 4.2 7.4.1.4.4.2): `float a, b, c;` and
  `long a[2], b;` in a struct or exception member (one field per name, each
  with the member's annotations, an array declarator applying to its own
  name), `typedef long A, B[2][3];` (one typedef per name; a typedef also
  takes several array dimensions now), `bitfield<3> a, b;`. A union branch
  keeps its single declarator, as the grammar says.
- `hddsgen::scope`: the one IDL 4.2 name resolver (7.5) the parser
  (constants, declaration order), the validator, the shared `TypeIndex` and
  every backend use.
- Floating-point literals with an exponent after a fraction (`1.5e3`),
  wide literals (`L'x'`, `L"text"`), character constants (`'\n'`), `::K`
  in constant expressions, union case labels naming a constant.
- `hddsgen::preprocessor`: the preprocessor the binary uses
  (`read_and_preprocess`, `preprocess_no_inline`, and `preprocess_str` for a
  source held in memory), so other tools need no copy of their own.
- **XCDR1 decoders in the C, C++, Python and TypeScript backends**
  (DDS-XTypes 1.3 7.4.1: the body of a `CDR_LE` / `PL_CDR_LE` sample), so a
  reader of these languages can request `[XCDR1, XCDR2]` and read a default
  DataWriter (which offers and encodes XCDR1, 7.6.3.1.1). Every structure
  and union gets an XCDR1 decoder next to its XCDR2 one: C
  `T_decode_cdr1_le[_at][_alloc]`, C++ `decode_cdr1_le[_at]`, Python
  `decode_cdr1_le`, TypeScript `decode<Name>Cdr1`; and a decoder picked from
  the encapsulation identifier (0x0001 / 0x0003 XCDR1, 0x0007 / 0x0009 /
  0x000b XCDR2, anything else refused): C
  `T_decode_by_encapsulation_alloc`, C++ `decode_by_encapsulation`, Python
  `decode_by_encapsulation`, TypeScript `decode<Name>ByEncapsulation`. The
  generated code declares it decodes XCDR1: `HDDSGEN_C_DECODES_XCDR1`,
  `HDDSGEN_CPP_DECODES_XCDR1`, Python `HDDS_DECODES_XCDR1`, TypeScript
  `HDDS_DECODES_XCDR1`. 8-byte values align at 8 from an origin reset at
  each parameter, no DHEADER, optional members of FINAL / APPENDABLE
  structures as parameters, MUTABLE structures and unions as parameter
  lists (short and `PID_EXTENDED` headers, `PID_IGNORE` skipped). Checked
  against every Cyclone DDS 0.11 XCDR1 body and the specification-built
  parameter-list vectors. TypeScript's `Cdr2Buffer` fields are `protected`.
  These backends have no XCDR1 encoder; C-micro has no XCDR1 decoder.
- **The extensibility of every C, C++, Python and TypeScript structure and
  union** (DDS-XTypes 1.3 7.2.2.4.4), which the encapsulation identifier of
  its samples names (7.6.3.1.2, Table 60: `CDR2_LE` FINAL, `D_CDR2_LE`
  APPENDABLE, `PL_CDR2_LE` MUTABLE): C `<NAME>_EXTENSIBILITY` and
  `<name>_extensibility()`, the value of `HDDS_EXTENSIBILITY_FINAL` (0),
  `_APPENDABLE` (1) or `_MUTABLE` (2) of the hdds C API; C++
  `T::hdds_extensibility` (the same numbers); Python
  `T.HDDS_EXTENSIBILITY` and TypeScript `extensibility<Name>` (`"final"`,
  `"appendable"`, `"mutable"`). The hdds SDK writers read it, so a sample of
  an APPENDABLE or MUTABLE type is no longer labelled `CDR2_LE`.
- **Rust backend: the key-payload hooks of a keyed type** (DDS-XTypes 1.3
  7.4.3.5.3, RTPS 2.5 9.6.4.8): `key_hash_of_key_payload` reads a key-only
  payload, XCDR1 or XCDR2 in either byte order as its encapsulation
  identifier says, and returns the KeyHash of the instance it names;
  `keys_round_trip` returns `true`, so endpoint creation sees a complete
  `encode_key` and reader pair. Bytes left after the key are refused
  (`None`), but for the zero padding bytes a sample may carry at its end.

- `--default-extensibility final|appendable|mutable` gives every un-annotated
  named type that extensibility (an enum or a bitmask stays APPENDABLE under
  `mutable`, DDS-XTypes 1.3 7.2.3 Table 12). Without it `hddsgen gen` prints
  an info line naming the types it generated as APPENDABLE.
- **`@mutable` unions** (DDS-XTypes 1.3 7.4.3.5.3 rules 27 and 28) in every
  backend (the micro backend under XCDR1 as a parameter list closed by
  `PID_LIST_END`, the others under XCDR2: a DHEADER, the discriminator as
  member 0 with the must-understand flag, then the selected case as a
  member). The decoder reads members by id, skips unknown
  ones, refuses an unknown must-understand member, and requires the
  discriminator.
- **Type evolution**: a reader accepts the data of a writer whose type has fewer
  members (7.4.1.2.3). The members it lacks take their default (zero, false,
  the empty string, sequence or map, the first enumerator, each array element at
  its default, a union at its default case; no value when optional) in every
  backend: an APPENDABLE member past the end of the DHEADER, and a `@mutable`
  member absent from the data (it was refused in C and C-micro); the micro
  backend does the first only. The Rust and micro backends gain
  `__hdds_default()` for it, the C backends `T__xdef` / `T_xdefault`.
- Union case labels of every kind: `TRUE` / `FALSE`, character literals,
  negative integers and scoped enumerators (`m::A`, `::m::A`), and annotations
  on a union discriminator.
- Rust backend: `try_xcdr1_size` / `try_xcdr2_size` report why a value cannot
  be encoded; `@try_construct` sets the `TRY_CONSTRUCT` member flags of the
  TypeObject.
- C++: `populate_from_json` on each `PubSubType` fills a generated type from a
  JSON document (`@optional` members: `null` resets them);
  `hdds_type_name` carries the IDL qualified name; `compute_key_with_protection`
  and `compute_protected_key` complete `compute_key`; each struct and union
  gets `hdds_compute_key`, `hdds_has_key` and `encode_key_cdr2_le[_at]`.
- C: `T_create_writer` and `T_create_writer_from_publisher` helpers announce
  the IDL type name.
- Decoder bounds on every decoding backend (Rust `MAX_ALLOC_RATIO` and
  `MAX_ZERO_WIRE_ELEMENTS`; C, C++, Python and TypeScript `CDR_MAX_ALLOC_RATIO`
  and `CDR_MAX_ZERO_WIRE_ELEMENTS`): one budget per decode, however the
  collections nest. See "Breaking changes since 1.0.12".

### Changed

- A decoder refuses an enumeration value that names no literal in C, C-micro,
  C++, Python and TypeScript (the micro backend reports `DecodingError`).
- Union case member ids are numbered from 1 for every union, the discriminator
  being member 0, and honour `@autoid(HASH)` and `@hashid`.
- Generated Rust is clippy-clean; enums carry
  `#[allow(non_camel_case_types, clippy::upper_case_acronyms,
  clippy::enum_variant_names)]`.

### Deprecated

- TypeScript: `Cdr2Buffer.readString()` and `Cdr2Buffer.writeString()` stay
  as deprecated aliases for existing callers. They now delegate to
  `getString()` / `putString()` and so align the string length to 4 bytes
  like them, per the XCDR2 rules; in 1.0.12 they did not align. New code
  calls `getString()` / `putString()`.

### Fixed

- C++ `FooPubSubType::type_name()` returns the IDL qualified name
  (`inner::Foo`), the string `hdds_type_name` carries, instead of the
  unqualified `Foo`.
- `--example` for Python is a live publisher and subscriber on the HDDS Python
  SDK instead of a stub with its DDS lines commented out. It reads the domain
  from `HDDS_DOMAIN_ID` like the other languages, waits for a matched reader
  before its first write, and the subscriber exits after 30 s without a
  sample. Both sides announce the scoped IDL type name (`m::T`), as the Rust
  backend does.

- `--example` publishers and subscribers for Rust, C++ and C read the domain
  from `HDDS_DOMAIN_ID` (default 0, a named constant) and print it. The
  publisher waits for a matched reader before its first write, and exits
  with a message after 30 s without one. The subscriber exits after 30 s
  without a sample and reports its count instead of waiting forever. The
  generated C subscriber now compiles against the SDK header (the waitset
  attach and wait calls it used do not exist). The generated Python example
  imports the IDL module (`from m import A`) instead of the invalid `from m
  import A.B`.

- Keyed C writer helpers announce the scoped IDL name, such as `m::T`,
  instead of its flattened C identifier. Participant and Publisher helpers
  use the existing IDL-name map for structures and unions.
- Nested key payloads preserve original must-understand annotations for
  mutable structures without explicit keys, matching the generated Rust
  encoder byte for byte (DDS-XTypes 1.3 7.2.2.4.7).

- Generated C, C++, Python and TypeScript types expose key-only XCDR2
  encoders with their original extensibility, declaration order and member
  ids (DDS-XTypes 1.3 7.2.2.4.7). They also compute the protected key digest
  with CDR big-endian alignment and unconditional MD5 (DDS-Security 1.1
  7.3.4), alongside the normal RTPS KeyHash. C typed operations pass both
  hashes and the key payload through the additive keyed C ABI; keyed writer
  constructors (`<type>_create_keyed_writer`) announce WITH_KEY; the existing
  C creation helpers keep their raw-byte behavior. C++ and Python SDKs consume
  the generated methods; TypeScript exports `hasKey<Name>`,
  `keySupported<Name>` and `encodeKey<Name>` for the typed writer. Keyed union
  discriminators use the same identity path as structures.

- Pretty-printer: `@topic` was dropped, and `@topic(name="X", platform="Y")`
  lost its parameters at parse time; both come back as written.
  `@verbatim` was dropped; it is printed with its three parameters.
- Pretty-printer: a string parameter of a custom annotation came back
  without quotes (`@foo(a="x y")` printed `@foo(a=x y)`, invalid IDL); each
  parameter is written as the literal kind it was read as, strings quoted
  and escaped. `@default`, `@min`, `@max`, `@range` values and annotation
  declaration defaults that are neither a number nor a name are quoted.
  `@unit` escapes its string. Booleans print as `TRUE` / `FALSE`.
- Pretty-printer: the annotations of a union branch (`case 1: @unit("s") long
  x;`) were dropped.
- An absolute name (`::T`) lost its `::` at parse time, so inside a module
  declaring its own `T` it named that one: the AST keeps it, the printer
  writes it back, the validator looks it up from the root only, and the
  backends' type index resolves an absolute or qualified name by its path
  from the root before its unqualified name. In the Rust and micro backends
  `::a::T` is generated as `__hdds_root::a::T`, through a root module every
  generated file now declares. An absolute base (`struct D : ::B`) and an
  absolute constant used as a bound are accepted.
- **`hddsgen check` overflowed its stack** on `typedef long T; module A {
  typedef T T; ... };`, and every backend emitted a typedef of itself
  (`typedef A_T A_T;`): a typedef saw its own name. A typedef's name is
  not in scope in its own type (`A::T` is the outer `T`, as Cyclone DDS
  reads it); a struct still sees its own (`sequence<Node>`). A typedef
  chain that names itself is a validation error, and the validator's
  typedef walk is bounded.
- `--namespace-cpp Outer` wrapped the generated text after the fact: the
  namespace opened inside a runtime include guard and every absolute name
  (`::A::P`) pointed outside it. The C++ generator now declares the types
  inside the namespace itself (`CppGenerator::with_namespace`), the
  runtime staying outside, and writes absolute names `::Outer::A::P`.
- Pretty-printer: a name used as an annotation value lost its escape
  (`@default(_octet)` printed `@default(octet)`, `@verbatim(placement=
  _struct)` became a string).
- Rust `TypeObject`: an array whose element is an alias (`MyLong l[3]`)
  described the element by the aliased type; it keeps the alias
  identifier, as Cyclone DDS does (the hash now matches idlc's).
- Function-like macros: a parameter list with spaces (`DECL(T, N)`), no
  parameter (`F()`), `#` stringizing and `##` token pasting
  (examples/macros now all generate).
- `@default('c')` (a character literal as an annotation value) is
  accepted; the Rust builder writes it as a `char`.
- C++: a constant named like a C++ keyword is escaped (`delete_`).
- **C++ did not compile a typedef reached from another module**:
  `module A { struct P { long v; }; typedef sequence<P> PList; }; module B {
  struct M { A::PList items; }; };` unrolled the alias into `B::M`'s
  decoder as `P x{};` ("'P' was not declared"); the Rust backend wrote
  `P` there too. The Rust, C++ and micro backends now generate from an AST
  whose references to types declared in a module (or sharing a name with
  another) are absolute, so an alias unrolled anywhere names the same
  type (`::A::P`, `__hdds_root::A::P`). The C++ JSON helpers looked enums
  and structs up by unqualified name; they use the shared index. A C++
  union whose branch is an alias of a sequence or string was generated as
  a raw union (does not compile); typedefs are followed.
- `@hashid` / `@hashid("name")` (DDS-XTypes 1.3 7.3.1.2.1.2) failed
  `hddsgen check` as an "unknown annotation" (with `@try_construct`,
  `@shared`, `@ignore_literal_names`, `@default_nested`); they are known.
  `@hashid` with `@id` on one member, or with a non-string argument, is an
  error.
- `hddsgen gen --out-dir DIR` wrote `mod.rs` whatever the language; it
  writes `mod.rs` for Rust and micro, else the input's name with the
  language's extension (`Shapes.hpp`, `Shapes.h`, `Shapes.py`,
  `Shapes.ts`), as `--separate` does.
- **Wrong key with two types of one name**: the backends' shared type index
  looked a type up by its unqualified name, the last declaration winning.
  `module B { struct X { @key long a; long b; }; }; module A { module B {
  struct X { long a; @key long b; }; }; module C { struct U { @key B::X k;
  }; }; };` hashed `k.a` (the root `B::X`) in the C++, Rust and micro
  backends instead of `k.b` (`A::B::X`, as Cyclone DDS reads it). A
  reference whose spelling a scope-less lookup would misread is now written
  as its absolute global name before generation, the index is keyed by
  global name, and module `@autoid`, nested `TypeObject`s and cycle
  detection follow the global name too.
- Validator: a relative name is the one the innermost enclosing scope
  declares (IDL 4.2 7.5); it was reported ambiguous whenever another module
  declared the same name.
- A name used before a nearer declaration of the same name (`X` in `M::U`,
  `M::X` declared after `U`) names the declaration visible where it is
  used, as Cyclone DDS reads it; it is pinned as `::X`.
- Pretty-printer: a string constant came back without quotes, a boolean
  as `true`, a character unquoted; each is written as an IDL literal of
  its type. Python: a boolean constant was `true`, a string unquoted.
- C++: a forward-declared union was declared `union U;` before its
  definition as `struct U`.
- Rust: `@default(BLUE)` on an enum member generated `unwrap_or(BLUE)`
  (does not compile); it is `Color::BLUE`.
- `Parser::new` (deprecated) swallowed a lexer error and parsed an empty
  file; `parse()` now returns that error.
- Rust backend: `X::builder()` called `XBuilder::default()`, which a member
  named `default` (now reachable as `_default`) shadowed.

- Rust backend: the key-only payload (`encode_key`) of a struct whose key
  member is a union now frames the union by the union's own extensibility, as
  the sample does: a DHEADER for an APPENDABLE union under XCDR2, the
  parameter-list members (discriminator as member 0 with must-understand, then
  the case) for a MUTABLE one. It wrote the FINAL form for every union.

- C++ JSON: `populate_from_json` combines a `\uXXXX` UTF-16 surrogate pair
  (`\ud83d\ude00`) into one code point (RFC 8259 7); it decoded the
  pair to two U+FFFD.
- C: the generated headers compile again when included from C++; four of them
  failed with an invalid conversion from `void*` after the allocator call.
- TypeScript: `Cdr2Buffer` keeps `readString()` and `writeString()` (see
  "Deprecated"), so a hand-written caller of the exported class still compiles.
- A derived structure serializes its base members first in every backend: they
  were not serialized in C, C++, Python, TypeScript and micro, not declared in
  C-micro, and a derived Rust structure did not compile. A TypeScript interface
  extends its base, and `computeKey` of a TypeScript type keyed in its base
  hashes the base key members.
- A union branch of type `string<N>` did not compile in Rust, micro and
  C-micro, nor did a C union whose enumeration discriminator has a literal
  holding a digit (case labels are numeric values now).
- A member of a typedef type did not compile or called a missing function: the
  micro backend ignored typedefs, C-micro did not declare them and TypeScript
  called an `encode<Alias>` that was never generated. Typedefs are resolved.
- C-micro: a member declared `char[64] sx;` (not valid C) is `char sx[64];`.
- C++: `sequence<boolean>` did not compile (address of a `vector<bool>`
  proxy); an empty FINAL structure compiles under strict flags (also in C);
  a nested structure or union is aligned against the stream, not against a
  sub-buffer of its own.
- C: `--c-standard c89` output did not compile as C89 (it does with `gcc
  -std=c89 -pedantic-errors`); a multi-dimensional array (`octet m[2][3]`)
  could not be declared; on a big-endian host the `_le` functions wrote the
  host representation.
- Rust: `sequence<8-byte>` under XCDR1 lacked the 8-byte alignment of its
  elements; a union `case 1: case 2:` decoded discriminator 2 into the default
  branch.
- Key digests: `@autoid(HASH)` at module level is honoured; a key of type
  `sequence<char>` / `sequence<wchar>` is an element count and the elements (no
  NUL) in every backend, where the digest counted a NUL and the C and C-micro
  `compute_key` did not compile.
- `hddsgen gen` of an `interface` or `exception` without the interfaces feature
  gives a clear diagnostic.
- `--example` projects request the hdds release this hddsgen targets; the
  generated micro project requests hdds-micro 1.5.0 and enables its `heapless`
  feature (the project did not build without it).
- An enumerator with no value takes the previous value plus one in every
  backend. The Rust, Rust micro, C-micro and TypeScript backends numbered it by
  its position instead (`enum E { A, B = 10, C }` gave `C = 2` there, 11 in
  Python, C and C++), so two peers generated from the same IDL disagreed on
  the wire. The Rust backends also emit `#[repr(i32)]` when an enumerator is
  negative, which `#[repr(u32)]` does not compile. The validator now refuses
  two enumerators with the same value and a value outside the Int8, Int16 or
  Int32 the `@bit_bound` selects (DDS-XTypes 1.3 7.2.2.4.1.1 Table 4, 7.4.1.1.3.1
  Table 32).

### Known limits

- Union `TypeObject`s differ from Cyclone DDS 0.11's in the member ids of
  the cases only: the discriminator is member 0 and the cases are
  numbered from 1 here (DDS-XTypes 1.3 7.3.1.2.1.1), Cyclone numbers the
  cases from 0. The test suite checks that renumbering Cyclone's cases
  gives our object exactly, so this is the ONLY difference; types holding
  a union differ by its hash.
- A typedef named like a C++ keyword is not escaped in C++.

- A TYPE, module or enumerator name that is a keyword of the target language
  (an escaped `_switch` as an enum name, `_case` as an enumerator) is not
  renamed by the C++, Rust, Python and TypeScript backends; member names are.
- The printer writes the value of a constant used as a bound or a case
  label, not its name (the AST keeps the value only).
- `bitfield<N, type>` (an explicit destination type) and anonymous
  bitfields (`bitfield<4>;`) are refused.
- A struct's own scope (IDL 4.2 7.5.2: a struct is a scope) and the
  "introduced into a scope by use" rule are not modelled.

- A bitset member is serialized as 8 bytes whatever its `@bit_bound` (Rust, C,
  Python and TypeScript); this is unchanged since 1.0.12.
- `fixed<D,S>` is a 16-byte little-endian integer in Rust, C and C++, not the
  packed form of the IDL `fixed`, and the Rust TypeObject of a `fixed` member
  does not describe that layout; Python and TypeScript raise, micro and
  C-micro refuse. This is unchanged since 1.0.12.
- C-micro generates nothing for a top-level bitset or for constants, and only
  refuses a bitset that a struct member uses.
